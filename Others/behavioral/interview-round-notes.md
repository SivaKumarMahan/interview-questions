# Scenario-Based Interview Notes

> Distributed from the former cross-topic scenario notes. Section numbering is retained where useful for interview practice.

## Behavioral & Leadership

Use the **STAR** method (Situation, Task, Action, Result) with concrete, quantified examples.

### 12.1 Conflict with a team member — how did you resolve it?
Describe a real disagreement (e.g. over an architecture choice), how you listened to understand their view, focused on data/shared goals rather than ego, sought common ground or escalated appropriately, and the positive outcome (decision made, relationship intact). Emphasize empathy, communication, and putting the project first.

### 12.2 How do you mentor junior engineers? (specific example)
Give a concrete instance: paired on a task, set incremental goals, did code reviews as teaching moments, encouraged ownership of a small project, and shared resources. Show the outcome (they grew into owning X). Emphasize patience, psychological safety, and gradually increasing autonomy.

### 12.3 Ideas you gave to improve deployments
Give real examples: introduced GitOps/Argo CD, added canary deploys to reduce incidents, automated a manual release step (saved N hours), added pre-deploy scanning, or created reusable pipeline templates. State the measurable impact (faster/safer deploys, fewer rollbacks).

### 12.4 How do you stay updated with new technologies / trends?
Blogs and docs (AWS/CNCF/Kubernetes), newsletters (DevOps'ish, KubeWeekly), conferences/talks (KubeCon, re:Invent), hands-on labs/POCs in a sandbox, communities (Reddit, HackerNews, CNCF Slack), certifications, and following release notes. Emphasize learning by building.

### 12.5 Approach to evaluating & adopting new tools
Identify the real problem first; evaluate against criteria (maturity, community, security, cost, integration, maintenance burden); run a **time-boxed POC** on a non-critical workload; compare alternatives; get team buy-in; roll out incrementally with a rollback plan. Avoid shiny-object adoption — solve an actual pain point.

### 12.6 How good are you at Linux / Python / AI in DevOps? (rating questions)
Answer honestly with evidence. **Linux/Python:** *"Strong — daily shell scripting, automation, troubleshooting; Python for tooling, boto3 automation, and data parsing."* **AI in DevOps (Copilot):** *"I use GitHub Copilot/Claude for boilerplate, test generation, and speeding up scripts, while reviewing all output for correctness and security."* Give a number and justify it.
