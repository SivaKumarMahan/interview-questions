# Prometheus Summary

Prometheus scrapes labeled numeric time series from configured or discovered targets and queries them with PromQL. `prometheus.yml` defines global evaluation/scrape intervals, scrape jobs, rule files and Alertmanager targets. With Prometheus Operator, `ServiceMonitor`, `PodMonitor`, `PrometheusRule` and related custom resources provide Kubernetes-native configuration.

Common exporters include node-exporter for host metrics, kube-state-metrics for Kubernetes object state, kubelet/cAdvisor for container usage and blackbox-exporter for synthetic network/application probes. Application `/metrics` endpoints should expose bounded labels; request IDs, user IDs and unbounded URLs must not become metric labels.

Production design covers persistent capacity, retention, resource requests, rule evaluation, failed scrapes, remote-write backpressure, cardinality and Prometheus self-monitoring. Multiple replicas improve availability but require a deduplication/query layer or managed service. Thanos, Mimir or a compatible managed backend can provide long retention and global querying.

Prometheus rules should express sustained actionable symptoms and SLO burn rather than every transient threshold. Validate configuration and rules with `promtool`, inspect Targets and rule health, safely reload, inject a test condition and verify resolution.

For Docker hosts, node-exporter exposes host CPU, memory, load, disk and network metrics while cAdvisor exposes container CPU, memory, filesystem and network usage. Prometheus scrapes both and Grafana displays host/container dashboards. Verify the full flow exporter -> Prometheus target -> query -> Grafana panel -> test alert, and restrict exporter/network access because operational metrics can reveal infrastructure details.
