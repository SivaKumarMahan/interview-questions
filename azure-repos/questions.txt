1. What is Azure Repos?
Answer: Azure Repos is the source control service in Azure DevOps. It supports Git repositories and Team Foundation Version Control, though Git is the common modern choice.

2. How do Azure Repos branch policies work?
Answer: Branch policies protect important branches by requiring pull requests, reviewers, build validation, work item linking, comment resolution, or minimum approvals before merge.

3. How do you enforce code review in Azure Repos?
Answer: Configure branch policies on `main` or release branches, require minimum reviewers, add required reviewers by path, enable comment resolution, and require successful build validation.

4. What merge strategies are available in Azure Repos?
Answer: Azure Repos supports merge commit, squash merge, rebase and fast-forward, and semi-linear merge depending on repository settings and branch policies.

5. How do you trigger Azure Pipelines from Azure Repos?
Answer: Configure YAML pipeline triggers for branches, paths, tags, or pull requests. Build validation policies can also trigger pipelines for PR checks.

6. How do you manage permissions in Azure Repos?
Answer: Use project groups, repository permissions, branch permissions, and least privilege. Restrict force pushes and direct pushes to protected branches.

7. How do you recover a deleted branch in Azure Repos?
Answer: Find the last commit from pull request history, pipeline logs, another clone, or reflog. Recreate the branch from that commit and push it back.

8. How do Azure Repos and GitHub differ?
Answer: Both host Git repositories. Azure Repos is tightly integrated with Azure DevOps Boards and Pipelines, while GitHub has broader open-source collaboration, Actions, Codespaces, and GitHub-native security features.
