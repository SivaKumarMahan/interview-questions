# AWS Networking Summary

## Internet Gateway vs. NAT Gateway

An Internet Gateway (IGW) is attached to a VPC and provides a route target for internet traffic. A resource in a public subnet is internet-reachable only when routing, a public IPv4/IPv6 address, security groups, network ACLs, and the host service all permit it. Typical public endpoints include internet-facing load balancers and deliberately exposed bastion patterns.

A NAT Gateway provides source NAT for outbound IPv4 connections from private subnets. Private instances route internet-bound traffic to the NAT Gateway; the NAT Gateway uses its public connectivity through an IGW. It does not accept unsolicited inbound connections to those private instances. NAT Gateway placement and routing should be designed per Availability Zone to avoid cross-AZ dependency and cost.

```text
Public workload: public subnet route -> IGW -> internet
Private egress:  private subnet route -> NAT Gateway -> IGW -> internet
```

Use VPC endpoints for supported AWS services when private access, policy control, availability, or NAT cost justify them. During troubleshooting, verify the subnet route table, NAT/IGW association, public or private address, security group, stateless network ACL return ports, DNS resolution, and flow logs. An IGW or NAT resource by itself does not prove end-to-end connectivity.
