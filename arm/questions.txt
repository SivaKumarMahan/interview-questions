1. What is an ARM template?
Answer: An ARM template is a JSON file that declaratively defines Azure resources and their configuration. Azure Resource Manager uses it to create or update infrastructure.

2. What are the main sections of an ARM template?
Answer: Common sections are `$schema`, `contentVersion`, `parameters`, `variables`, `resources`, and `outputs`.

3. What is the difference between ARM and Bicep?
Answer: ARM templates are JSON and can be verbose. Bicep is a simpler language that compiles to ARM templates. Both deploy through the Azure Resource Manager engine.

4. How do parameters and variables differ in ARM templates?
Answer: Parameters accept input values at deployment time. Variables define reusable calculated values inside the template.

5. What is `dependsOn` in ARM templates?
Answer: `dependsOn` explicitly defines resource deployment order. ARM can infer some dependencies from resource references, but `dependsOn` is useful when the relationship is not obvious.

6. How do you deploy an ARM template?
Answer: Use Azure CLI, PowerShell, Azure Portal, or a CI/CD pipeline. Example: `az deployment group create --resource-group rg-demo --template-file template.json --parameters @parameters.json`.

7. How do you manage secrets in ARM templates?
Answer: Use secure parameters, Key Vault references, managed identities, and deployment permissions. Avoid hardcoding secrets or exposing them through outputs.

8. What is ARM template `copy` used for?
Answer: `copy` creates multiple instances of a resource or property by looping over a count. It is useful for repeated resources like NICs, disks, or similar VMs.

9. How do you preview ARM template changes?
Answer: Use `az deployment group what-if` or the equivalent PowerShell command to preview what resources will be created, modified, or deleted.

10. How do you troubleshoot ARM deployment failures?
Answer: Review deployment operations, error details, resource provider registration, policy denials, naming rules, region support, quotas, and RBAC permissions.
